# proof-log.jsonl, explained

`.claude/learning/progress/proof-log.jsonl` is the proof of what the user has learned. A JSONL file cannot hold comments, so this file explains it. The template for one entry is `.claude/templates/proof-entry.md`.

## The rule behind it

**Only the user's own words are proof.** Every entry quotes the user, and the quote is checked word for word against their real messages. What the tutor explains, shows or says is never proof and is never recorded. If there is no quote, there is no entry.

## The format

JSONL means one JSON entry per line (JSON is a text format of names and values). The tutor only ever adds a line at the end, so the file is never rewritten, and a broken line breaks only itself. The file can grow for years: the tutor reads only its last lines before adding one.

| Field | Required | What to write |
|---|---|---|
| `timestamp` | yes | The date and time of the user's message that holds the quote, as `2026-10-06 15:39`, on the user's clock. Take it from the time line the hook adds to each message. |
| `concept` | yes | The concept's ID from the skill tree in `.claude/learning/skill-tree/`, such as `git-commit`. |
| `kind` | yes | What the user showed: one of the kinds below. |
| `quote` | yes | The user's own words, copied exactly from their message. Capital letters and spaces may differ; every word must match. Choose the part that shows the understanding or the action. |
| `note` | no | A few words of context, for example which part of "Knowing it means" is still missing. |
| `source` | no | Only when the quote is not in this project's chat file of that day: the path of the file that holds it, for example a file of the user's messages copied from an earlier project into this folder. |

A double quote mark inside a value is written as `\"`.

## The kinds

| Kind | When | Status it gives |
|---|---|---|
| `did` | the user did it themselves, and their message shows it (for example the command they typed) | in progress |
| `partial` | the user explained part of it correctly | in progress |
| `explained` | the user explained it fully in their own words, covering "Knowing it means" in the skill tree | learned |
| `answered` | the user answered a check question about it correctly | learned |
| `missed` | the user answered wrongly or showed they forgot; quote the wrong answer | one step down |

The status of a concept comes only from these entries, applied in timestamp order: the script `.claude/hooks/shared/learning_state.py` calculates it, and `.claude/hooks/after-file-change/update-learning-pages.py` shows it in the pages of this folder.

## Example

The user wrote, at 15:39: "a commit saves my files at one moment, with a message that says what changed". That is a full explanation of a commit, so the tutor adds:

```json
{"timestamp": "2026-10-06 15:39", "concept": "git-commit", "kind": "explained", "quote": "a commit saves my files at one moment, with a message that says what changed"}
```

## Adding, and the only case for changing a line

1. Read only the last lines of the file, then add the new line after the last line with the Edit tool, in the same answer in which the proof happens.
2. The page hook runs at once: it checks the entry and rebuilds the pages. If the entry does not count (an unknown concept, a missing quote, a quote that is not found), it tells you right away.
3. An old line is history: never change or delete it, with one exception. You may correct a line, in place, when it never counted, when its kind is wrong (it claims more or less than the quote shows), or when the file in its `source` moved. None of these is real history, so nothing is lost. Never change a line to raise a status without new words from the user.

## Other files in this folder

- `overview.md` and one page per subject are generated by the page hook; never edit them.
- When the user moved here from an earlier project, a file of their messages copied from it can sit here too; the entries that quote it name it in their `source`.
- How to start fresh when `.claude/` is copied for a new user is the first step of `.claude/skills/onboard/SKILL.md`.
